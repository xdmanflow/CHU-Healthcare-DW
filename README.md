## About the Project

CHU (Cloud Healthcare Unit) is a hospital group undergoing a major digital transformation, seeking to leverage the considerable volume of data generated by its healthcare management systems and FTP systems. Its data — patient traffic, medical records, service tracking, cycle times, and facility profitability — was scattered across disparate, heterogeneous sources (a PostgreSQL database, CSV exports, and flat files), making it difficult to extract actionable insight for practitioners and administrators.

To address this, the project designs and implements a scalable **data warehouse** capable of integrating these distributed sources into a single persistent source, enabling exploration, visualization, and secure data mining to support better decision-making — from monitoring patients and deaths at a national level to tracking long-term satisfaction trends.

## Deliverables

### Deliverable 1 — Data Repository

Conceptual model of the data and jobs needed to feed the decision-making schema, including:

- Modeling of the various analysis areas and measures
- Development of ETL jobs feeding into the decision-making schema
- Description of the data warehouse architecture

*(Format: Report)*

### Deliverable 2 — Physical Model & Optimization

Physical model and performance assessment based on query response times, including:

- Scripts for creating and loading data into tables
- Verification of existing data and table access
- Scripts showing table population
- Scripts for partitioning and bucketing
- Graphs assessing data warehouse access performance
- Queries used as the basis for performance evaluation

*(Format: Report + zip file containing the various jobs)*

### Deliverable 3 — Presentation of Results & Storytelling

Presentation of the decision-making system built for CHU, interpreting results through a dashboard-driven narrative aimed at influencing decision-makers and practitioners, covering:

- Methodology adopted for designing the Big Data decision-making system
- Requirements for managing patients' medical activities
- Design and construction of the data warehouse
- Restitution and storytelling
- Technical demonstration

*(Format: 20-minute oral presentation + 10 minutes of Q&A)*

## Data Warehouse Architecture Overview

| Component | Solution |
|-----------|----------|
| ETL / Integration | Talend Open Studio for Big Data (TOS_BD) |
| Operational data source | PostgreSQL — patient medical & administrative records |
| External data sources | CSV export (French hospital management), flat files (FTP) |
| Modeling approach | Dimensional modeling (star/snowflake schema) |
| Storage | Data warehouse / data marts |
| Reporting | Python (`build_docx_reports.py`) for automated report generation |
| Dashboard & visualization | BI dashboard for restitution and storytelling |

## Key Analytical Requirements

- Patient consultation rate by facility over a given period
- Consultation rate relative to diagnosis over a given period
- Overall hospitalization rate over a given period
- Hospitalization rate relative to diagnosis over a given period
- Hospitalization rates by gender and age
- Consultation rate per healthcare professional
- Number of deaths by region (2019)
- Overall satisfaction rate by region (2020)
